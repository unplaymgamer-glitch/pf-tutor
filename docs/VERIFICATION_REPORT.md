## Security and privacy review
- Headers on every page: CSP (self + pinned mirrors for the wasm compiler, `wasm-unsafe-eval`, no framing), HSTS, nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options. Admin: stricter CSP, `noindex`, `no-store`.
- `npm audit`: **0 vulnerabilities**; lockfile committed. No third-party scripts; fonts are self-hosted. Compiler files are SHA-256 pinned.
- No secret in client JS (scan above). `.env.local` is git-ignored; `.env.example` has names only.
- RLS enabled with no policies; anonymous client cannot read or write protected tables (32 negative tests against the real database, run earlier with the anon key).
- Known weak points: CSP keeps `'unsafe-inline'` for scripts and styles (Next.js inline bootstrap); the admin path is obscure but security does not depend on that.
- Privacy page written from what the code actually stores (`/privacy`).

## Known limitations
1. Performance score below 90 on the throttled mobile profile (see 9).
2. Firefox, Safari, Android and iOS untested; low-RAM phones may fail the full compiler (fallbacks exist).
3. Real AI quality unmeasured until an API key is added.
4. Lesson wording was machine-verified for code correctness, but nobody has read all 79 lessons for teaching quality; Urdu-script lesson text is not written.
5. Week 15 graphics is a simulation of the notes' `graphics.h` subset, not real Turbo C++/WinBGIm output.
6. The shared Supabase project could pause if unused for 7 days (a daily cron ping is configured in `vercel.json`).
